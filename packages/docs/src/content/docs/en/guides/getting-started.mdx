## 1. Introduction

Croco provides a **SaaS backend toolkit** — fully typed, with auth, metering, billing, tenant
isolation, REST contracts, and operational diagnostics built into the framework. The `saas-api`
goal selects the supported generated stack and records it in `croco.app.json`.

This guide follows one executable loop: generate the REST SaaS workspace, install it, pass its
zero-credential demo smoke, inspect its routes, and extend the same generated controller.

<Aside type="tip" title="Prefer a fully working example?">
  Jump straight to
  [`examples/quick-start-lambda`](https://github.com/croco-dev/framework/tree/trunk/examples/quick-start-lambda)
  for a separate Lambda reference with auth, metering, and DI wiring. For a billing-oriented
  reference, use
  [`examples/saas-billing-golden-path`](https://github.com/croco-dev/framework/tree/trunk/examples/saas-billing-golden-path).
</Aside>

## 2. Quick Start

Create the canonical SaaS REST workspace with the CLI:

```bash
npx create-croco-app@latest my-saas-api --goal saas-api --scope @myorg --no-install --no-git
```

This runs noninteractively with the `saas-api` goal and `@myorg` package scope. It generates a REST
SaaS workspace with `apps/api-server/src/controllers/SaasController.ts`,
`apps/api-server/src/controllers/OperationsController.ts`, provider and tenant manifests, and a
`croco.app.json` goal contract. Replace `@myorg` with your package scope.

Install dependencies and run the documented success scenario:

```bash
cd my-saas-api && pnpm install && pnpm demo:smoke
```

Success means `demo:smoke` completes the generated REST contract checks, in-memory SaaS demo flow,
and operational smoke without external credentials. It does not start a long-running server.

## 3. Inspect the Generated REST API

The generated Node REST application registers
`apps/api-server/src/controllers/SaasController.ts` and
`apps/api-server/src/controllers/OperationsController.ts`. `SaasController` exposes the local demo
routes under `/saas`; `OperationsController` exposes health and diagnostics under `/ops`.

Start that generated application with its demo endpoints enabled:

```bash
SAAS_DEMO_ENDPOINTS_ENABLED=true pnpm --filter @myorg/api-server dev
```

In another terminal, seed the in-memory SaaS runtime and read the deterministic smoke result:

```bash
curl -X POST http://localhost:3000/saas/demo/seed
curl http://localhost:3000/saas/demo/smoke
curl http://localhost:3000/ops/health
```

The `/saas/demo/*` routes are disabled unless `SAAS_DEMO_ENDPOINTS_ENABLED=true` and remain disabled
in production. The CLI `pnpm demo:smoke` path does not require opening those HTTP routes.

## 4. Extend the Generated Controller

Add REST behavior in `apps/api-server/src/controllers/SaasController.ts`, where the generated app
already keeps route metadata and Problem responses together:

```typescript no-check
@Controller("/saas")
export class SaasController {
  @Post(seedSaasDemoRoute)
  @ProblemResponses(...routeProblemResponses(seedSaasDemoRoute))
  async seedDemo() {
    await assertDemoEndpointsEnabled();
    const { seedDefaultSaasRuntime } = await import("../saasDemo");
    return seedDefaultSaasRuntime();
  }

  @Get(smokeSaasDemoRoute)
  @ProblemResponses(...routeProblemResponses(smokeSaasDemoRoute))
  async smokeDemo() {
    await assertDemoEndpointsEnabled();
    const { seedDefaultSaasRuntime } = await import("../saasDemo");
    return seedDefaultSaasRuntime();
  }
}
```

After changing route metadata or behavior, re-run the generated contract and success gates:

```bash
pnpm contract:check
pnpm demo:smoke
```

`contract:check` fails on invalid REST schemas or Problem contracts. `demo:smoke` then proves the
same generated workspace still passes profile, architecture, runtime-policy, contract, SaaS flow,
operations, and job checks.

## 5. Separate Checked-in References

The scaffold journey is complete at this point. For deployment-specific or deeper domain examples,
use these separate checked-in references rather than treating them as generated files:

- [`examples/quick-start-lambda`](https://github.com/croco-dev/framework/tree/trunk/examples/quick-start-lambda)
  demonstrates Lambda export, auth, metering, and DI wiring. Validate it with
  `pnpm quick-start-lambda:smoke`.
- [`examples/saas-billing-golden-path`](https://github.com/croco-dev/framework/tree/trunk/examples/saas-billing-golden-path)
  demonstrates checkout, retry, transactional events, audit projection, and explicit Problem
  recovery. Validate it with `pnpm saas-billing-golden-path:smoke`.

The repository-level `pnpm first-success:verify` gate keeps the public scaffold commands and this
generated SaaS route/runtime walkthrough aligned with the actual CLI contract.
